# PLAAI Group — แดชบอร์ดวิเคราะห์ผลประกอบการ (P&L)

เว็บแอปหน้าเดียวสำหรับดูงบกำไรขาดทุนรายเดือนของโรงแรมในเครือ เปรียบเทียบปีต่อปี และนำเสนอผู้บริหาร

**เปิดใช้งาน:** https://plaai-crm.github.io/Plaai-PL-for-Acc/

## ⚠️ กติกาความปลอดภัย — อ่านก่อนแก้ไขหรือเพิ่มไฟล์

repository นี้เป็น **สาธารณะ** ทุกไฟล์ที่อยู่ในนี้ **ใครก็อ่านได้** โดยไม่ต้องล็อกอิน

**ห้ามใส่ในนี้เด็ดขาด:**

- ❌ ไฟล์ SQL ที่มีข้อมูล P&L จริง (`supabase_seed.sql` / `.txt`)
- ❌ ไฟล์ Excel/CSV ที่มีตัวเลขผลประกอบการจริง
- ❌ รหัสผ่านของผู้ใช้ ไม่ว่าจะรูปแบบใด
- ❌ `service_role` key ของ Supabase
- ❌ ตัวเลขจริงในตัวแปร `SEED` ใน `index.html` (ตัวแปรนี้มีไว้สำหรับ **ข้อมูลสมมติ** เพื่อทดลองใช้เท่านั้น)

**ที่อยู่ในนี้ได้ปลอดภัย:**

- ✅ `SUPABASE_URL` และ `SUPABASE_ANON_KEY` — สองค่านี้ออกแบบมาให้เปิดเผยได้
  เพราะสิทธิ์ทั้งหมดถูกบังคับด้วย Row Level Security ที่ฐานข้อมูล
  **ผู้ที่ไม่ได้ล็อกอินจะอ่านอะไรไม่ได้เลยแม้จะมี key นี้**

ข้อมูลจริงทั้งหมดอยู่ในฐานข้อมูล Supabase เท่านั้น

## สถาปัตยกรรมความปลอดภัย

```
เบราว์เซอร์ ──(username + password)──► ฟังก์ชัน app_login() บน Postgres
                                        ├─ ตรวจรหัสด้วย bcrypt
                                        ├─ ล็อกบัญชี 15 นาที ถ้าผิด 5 ครั้ง
                                        └─ คืน session token (อายุ 12 ชม.)

เบราว์เซอร์ ──(header: x-app-token)──► PostgREST ──► RLS policy
                                                      ├─ ไม่มี token = อ่านไม่ได้เลย
                                                      ├─ ผู้จัดการ = เห็นเฉพาะโรงแรมใน scope
                                                      ├─ ฝ่ายบัญชี = เห็น/แก้ได้ทุกโรงแรม
                                                      └─ เจ้าของ = + จัดการผู้ใช้ + ดูประวัติแก้ไข
```

สิทธิ์ถูกบังคับที่ **ฐานข้อมูล** ไม่ใช่ที่หน้าเว็บ — แก้ JavaScript ในเบราว์เซอร์แล้วก็ยังดึงข้อมูลโรงแรมอื่นไม่ได้

**ตารางในฐานข้อมูล:** `hotels` · `pl_monthly` · `insights` · `app_users` · `app_sessions` · `app_login_attempts` · `pl_audit`

**ฟังก์ชัน:** `app_login` · `app_logout` · `app_touch` · `app_list_users` · `app_save_user` · `app_delete_user` · `app_audit`

## หลักการคำนวณที่ควรรู้

- **เทียบเฉพาะเดือนที่มีข้อมูลครบทั้งสองปี** — เดือนที่ขาดข้างใดข้างหนึ่งจะถูกตัดออก และมีแถบแจ้งไว้เหนือ KPI
- **Margin และ Occupancy** แสดงการเปลี่ยนแปลงเป็น **จุด (percentage point)** ไม่ใช่ %
- **Occ / ADR / RevPAR** เป็นค่าเฉลี่ยถ่วงน้ำหนักตามจำนวนห้องคืน (คำนวณจาก รายได้ห้องพัก ÷ RevPAR)
  ถ้าข้อมูล RevPAR ไม่ครบจะถอยไปใช้ค่าเฉลี่ยอย่างง่ายและแจ้งไว้
- **ช่องยอดรวมในหน้ากรอกข้อมูล** (รายได้รวม / ค่าใช้จ่ายรวม / GOP / รวมใต้ GOP / กำไรสุทธิ) คำนวณอัตโนมัติและแก้ไม่ได้
  ฐานข้อมูลยังมี CHECK constraint กันอีกชั้น ตัวเลขจึงบวกลงตัวเสมอ
- **รายการใต้ GOP** กรอกเป็นจำนวนเงินบวก ระบบจะแปลงเป็นค่าลบให้เอง

## รูปแบบไฟล์นำเข้า

หัวคอลัมน์ต้องตรงกับเทมเพลต (ดาวน์โหลดได้จากแท็บ "กรอกข้อมูล" → ⬇ ดาวน์โหลดเทมเพลตเปล่า)
รองรับ `.xlsx` `.xls` `.csv` — ไฟล์ CSV ภาษาไทยรองรับทั้ง UTF-8 (มี/ไม่มี BOM) และ windows-874

คอลัมน์บังคับ: `รหัสโรงแรม` · `ปี(ค.ศ.)` · `เดือน(1-12)`
ช่องยอดรวมในไฟล์จะถูกคำนวณใหม่จากรายการย่อยเสมอ ถ้าไม่ตรงระบบจะแจ้งเตือนแต่ยังนำเข้าให้
